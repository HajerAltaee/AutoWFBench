# Recorded protocol benchmark/examples

`solutions/` contains replaceable solution manifests. The reference API implements
both scenarios and is deliberately scripted, not an autonomous AI workflow.

The following artifacts were generated by an actual CRM reference execution and
an independent `codex exec` judge on 2026-10-04:

- `submission.json`: what the solution returned.
- `run-log.json`: what the engine assembled from all four evidence sources.
- `package.json`: the exact definition/environment/scorecard used by the run.
- `judge-response.json`: validated model response plus service-recorded provenance.
- `scorecard-result.json`: deterministic aggregation of verified facts and judge answers.

Judge model: `gpt-6-astra`. Judge prompt version: `1.0.1`. The reference received
10/10. **This demonstrates a functioning execution/judging pipeline; it is not a
performance result for a WF-specialist's submission or proof of judge calibration.**

The full request and CLI execution records are saved locally by the judge service;
only synthetic, portable result artifacts are committed here. The sample includes
actual run/event IDs and hashes. Ephemeral network endpoints identify a past local
run and are not usable service addresses. Start your own API using the manifests.

Demo command results are separate and use a clearly simulated judge. Do not mix
their scores with the recorded real judge response.
